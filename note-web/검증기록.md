# 1단계 구현·검증 기록

검증일: 2026년 10월 23일

현재 상태: **시제품 구현과 PC 확인 완료. 실제 아이패드 확인 대기.**

## 2026년 10월 24일 — 기본 100%, 배율 10~100%

- ‘10%까지만’은 최소 축소 배율로 해석했다. 페이지 열기·페이지 미리보기 선택·100%로 보기에서 100%를 적용한다. 재접속 시 마지막 화면 중심은 유지한다.
- 버튼·휠·두 손가락 확대 계산은 모두 10~100%로 제한한다. 한도에 도달한 확대·축소 버튼은 비활성화한다. 페이지 썸네일은 먼 곳의 획도 모두 보이도록 별도로 맞춘다.
- 이전 버전의 5% 등 범위 밖 배율 데이터도 계속 읽는다. 필기를 변경하지 않고 열 때의 배율만 100%로 맞춘다.
- 문법 검사와 자동 검사 **25개 통과**. 화면 크기별 100% 시작, 과거 배율로 저장한 위치 유지, 반복 확대·축소 한도와 기준점 유지, 배율 한도에서 두 손가락 이동 계산을 확인했다.
- PC 브라우저에서 100% 시작·확대 버튼 비활성화, 반복 축소 후 10%·축소 버튼 비활성화, 추가 휠 축소에도 10% 유지, 페이지 선택 후 100%, 80%에서 새로고침 후 100%를 확인했다.
- 아래의 5% 및 배율 복원 기록은 이번 변경 이전 동작이다. 실제 아이패드 확인은 별도로 남아 있다.

## 2026년 10월 24일 — 흰 화면 전체 필기

- 고정 크기 종이의 경계·입력 제한·화면 이동 제한을 제거하고 무한 캔버스로 변경했다. 흰 작업면 어디서나 쓰고 사방으로 이동할 수 있다.
- 줄·격자는 현재 보이는 영역을 기준으로 이어서 그린다. 기존 획 좌표는 변환하지 않는다.
- 전체 보기는 종이 크기가 아닌 실제 필기 범위에 맞춘다. 마지막 화면 위치·배율도 저장한다.
- 문법 검사 통과. 자동 검사는 기존 17개에 무제한 좌표, 안내선 범위, 멀리 떨어진 글씨 전체 보기, 화면 위치 복원, 잘못된 보기 데이터 검사를 더해 **22개 통과**했다.
- PC 브라우저에서 5%로 축소한 뒤 왼쪽·오른쪽 끝에 각각 선을 작성했다. 기존 확대 종이의 경계보다 먼 영역에서도 선이 표시되고 저장됐다.
- 새로고침 뒤 두 선과 5% 보기 위치가 그대로 남는 것을 확인했다.
- 실제 아이패드 검증은 여전히 남아 있다.

아래 내용은 최초 시제품의 확인 기록이다.

## 자동 검사

- `npm.cmd run check`: JavaScript 모듈·서버 문법 검사 통과.
- `npm.cmd test`: 17개 검사 통과, 실패 0개.
- 부분 지우개: 긴 획 일부 자르기, 점 지우기, 빠른 이동 중 누락 방지, 원본 불변성.
- 좌표: 확대·두 손가락 이동 시 기준 문서 좌표 유지.
- 입력: 마우스·Shift 이동, 화면 고정, 손가락 필기 우선순위, 두 손가락 전환 시 임시 획 취소, 펜 입력 중 손가락 억제.
- 저장 형식: 최신 임시 기록 복구 선택, 손상 데이터 덮어쓰기 방지, 잘린 획의 압력·시간 보존.

## PC 브라우저에서 직접 확인

| 확인 | 결과 |
| --- | --- |
| 로컬 HTTP 응답 | 200 확인 |
| 마우스 필기 | 선과 페이지 미리보기 표시, 저장 완료 표시 확인 |
| 부분 지우개 | 긴 선의 가운데만 지워지고 양쪽 선 유지 |
| 실행 취소 | 지우기 전의 연결된 선 복원 |
| 다시 실행 | 같은 구간이 다시 지워짐 |
| 새로고침 | 부분 지우기 결과 유지 |
| 안내선 변경 | 무지에서 격자로 변경, 필기 유지 |
| 확대 | 28%에서 35%로 변경 |
| 화면 고정 | 전체 보기·확대·축소 버튼 비활성화, 휠 확대 차단 |
| 고정 중 필기 | 새 선을 쓰고 자동 저장 확인 |
| 태블릿 폭 | 768 × 1024 프레임에서 화면 확인 |
| 모바일 폭 | 390 × 844 프레임에서 잘리던 도구 배치를 수정하고 재확인 |

화면 크기는 데스크톱 브라우저 안의 프레임으로 확인했다. iPadOS Safari 실행이나 실제 터치·펜 검증을 완료했다는 의미가 아니다. 검사 표본은 `127.0.0.1` 주소에서 사용했으며 사용자 미리보기는 `localhost` 주소의 빈 노트로 열었다.
