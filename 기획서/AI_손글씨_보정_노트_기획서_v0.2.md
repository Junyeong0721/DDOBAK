# AI 손글씨 보정 노트 서비스 기획서

버전 0.2 · 수정일 2026년 10월 23일

대학생과 시험 준비생이 직접 쓴 필기를 자기 글씨체 그대로 정돈하고, 일상적인 필기와 손글씨 연습을 함께 할 수 있는 서비스다. 아이패드에서 실제로 사용할 반응형 웹을 만들며, 컴퓨터는 개발과 마우스 테스트에 사용한다. 큰 페이지를 확대·축소하며 쓰고 필요할 때 새 페이지를 추가한다. 첫 출시의 중심은 손글씨 보정과 손글씨 연습이며, PDF 강의자료 필기는 이후에 추가한다.

이 문서는 현재 확정된 제품 방향, 첫 출시 기능, 화면과 사용 흐름, 기술 검증 순서, 추가 결정 질문을 정리한다. ‘확정’은 현재 결정된 기획 사항이며 개발이 완료되었다는 뜻은 아니다. ‘제안’은 검토할 기본안, ‘미정’은 추가 답변이 필요한 사항이다.

## 1 제품 방향

### 확정된 사항

| 항목 | 결정 내용 |
| --- | --- |
| 핵심 사용자 | 대학생과 시험 준비생 |
| 서비스 형태 | PC에서 확인하고 실험하는 모바일 웹으로 시작 |
| 기기 역할 | 아이패드에서 실제 사용과 일부 테스트 · 컴퓨터에서 개발과 마우스 테스트 |
| 보유한 테스트 기기 | 아이패드 · 정확한 모델과 운영체제 버전은 미정 |
| 개발 방식 | 개발 경험이 적은 1인이 AI 도구의 도움을 받아 개발 |
| 진행 방식 | 고정 일정 없이 질문과 작은 시제품 확인을 반복하며 구체화 |
| PC 실험 입력 | 마우스를 사용할 예정 |
| 필기 입력 | 서비스 안의 노트에 직접 쓴 글씨 |
| 노트 화면 | 크기가 정해진 큰 페이지에 필기하고 확대·축소 · 다 쓰면 새 페이지 추가 |
| PC 페이지 이동 | 평소에는 필기 · Shift를 누른 채 드래그하면 페이지 이동 |
| 보정 스타일 | 자기 글씨체를 유지하며 자연스럽게 정리 |
| 보정 우선순위 | 글자 사이 간격과 전체적인 정돈 상태 |
| 보정 범위 | 원래 위치와 줄 구성을 최대한 유지하며 조금만 조정 |
| 보정 시점 | 자동 보정과 선택 후 보정을 모두 제공하며 사용자가 선택 |
| 허용 대기 시간 | 보정 결과가 나올 때까지 1~3초 정도 기다릴 수 있음 |
| 보정 언어 | 한글·영어·숫자 |
| 손글씨 연습 | 자기 글씨 다듬기와 제공되는 예쁜 글씨 따라 쓰기 모두 제공 |
| 연습 글씨체 선택 | 여러 예시를 먼저 보여주고 사용자가 고르게 함 |
| 네트워크 | 인터넷 없이 필기 가능 · AI 보정에는 인터넷 사용 가능 |
| PDF 자료 위 필기 | 빈 노트 기능을 먼저 만들고 이후 추가 |

초기에는 실제 사용 기기인 아이패드에 노트를 저장하는 방식을 제안한다. PC에서는 개발·테스트용 노트를 사용하며, PC와 아이패드 사이의 자동 동기화는 현재 사용 흐름의 필수 기능으로 두지 않는다. 백업과 테스트 자료 이동에는 파일 내보내기·불러오기를 제안한다.

### 서비스의 목표

빠르게 작성한 필기를 읽기 좋게 정리하되, 사용자가 자신의 글씨라고 느끼게 한다. 보정 과정에서 발견한 간격·정렬 습관은 짧은 연습으로 연결한다. 보정된 결과의 보기 좋은 정도와 사용자의 실제 글씨 실력 향상은 각각 검증한다.

핵심 사용 경험은 ‘필기 → 필요한 부분 정돈 → 복습’과 ‘연습 → 구체적인 피드백 → 다시 쓰기’다. 두 흐름은 연결하되 공부 중 연습을 강요하지 않는다.

## 2 해결할 문제와 검증할 가설

다음은 사용자 인터뷰와 실제 사용으로 확인할 가설이다.

- 강의나 문제 풀이 중 급하게 쓰면 글자 간격이 불규칙해져 복습하기 불편하다.
- 손글씨를 다시 쓰는 데 시간을 쓰고 싶지 않지만, 개성 없는 글씨체로 바뀌는 것도 원하지 않는다.
- 손글씨를 연습하고 싶어도 자신의 어떤 부분을 고치면 되는지 알기 어렵다.
- 별도의 긴 연습보다 실제 노트에서 발견한 습관을 짧게 연습하는 방식이 지속하기 쉽다.

주요 사용 장면은 강의 요약, 시험 개념 정리, 암기 노트 작성이다. 수식·도표가 섞인 필기는 글씨 영역과 구분해 보호한다. 수식 자체의 보정은 첫 출시 범위에 포함하지 않는 것을 제안한다.

## 3 핵심 기능 하나 손글씨 보정

### 사용 흐름

1. 사용자가 노트를 열어 자유롭게 필기한다.
2. 선택 보정에서는 영역을 선택하고 ‘정돈하기’를 누른다.
3. 자동 보정에서는 필기를 잠시 멈춘 뒤 완성된 구간을 처리한다.
4. 보정 결과를 표시하고 원본 비교와 되돌리기를 제공한다.
5. 사용자가 이어 쓰거나 결과를 수정해도 원본과 변경 이력을 보존한다.

선택 보정은 미리보기 후 적용하는 방식을 기본안으로 한다. 자동 보정은 사용자가 켠 경우에만 동작하며, 첫 사용 기본값은 꺼짐을 제안한다. 사용자는 보정 결과를 1~3초 정도 기다릴 수 있다. 이를 사용자 체감 대기 시간의 목표로 삼고 실제 성능은 시제품에서 측정한다.

선택 보정은 버튼을 누른 때부터, 자동 보정은 마지막 획을 쓴 뒤 멈춘 때부터 결과가 보일 때까지 측정하는 것을 제안한다. 자동 보정의 멈춤 감지 시간과 서버 처리 시간을 합쳐 사용자가 오래 기다리지 않도록 조정한다. 처리 중에도 대상 밖의 필기를 이어갈 수 있어야 한다.

### 보정 항목과 적용 원칙

| 항목 | 첫 출시 방향 | 지켜야 할 조건 |
| --- | --- | --- |
| 글자 사이 간격 | 우선 구현 | 같은 단어 안의 간격을 작게 정리하고 원문 띄어쓰기는 보존 |
| 단어 사이 간격 | 보수적으로 정리 | 띄어쓰기를 새로 만들거나 없애지 않음 |
| 줄 정렬 | 작은 범위에서 지원 제안 | 기존 줄과 문단 소속을 유지 |
| 글자 크기 편차 | 보조 기능으로 검토 | 제목·강조·첨자처럼 의도된 차이는 유지 |
| 획 떨림 | 약한 보조 기능으로 검토 | 특징적인 꺾임·받침·작은 점을 보존 |
| 자음과 모음 재배치 | 후속 검증 | 한글 음절을 다른 글자로 바꾸는 위험을 먼저 확인 |
| 다른 글씨체로 변환 | 노트 보정 범위에서 제외 | 사용자가 선택한 자기 글씨체 유지 방향을 따름 |
| 문법·맞춤법·내용 변경 | 노트 보정 범위에서 제외 | 필기 내용과 의미를 보존 |

‘전체적으로 정돈’은 페이지를 새로 배치한다는 의미가 아니다. 원래 줄 안에서 글자 간격과 기준선을 조금씩 맞춰 정돈된 인상을 주는 것이 목표다. 이를 위해 이동량 상한을 글자 크기에 비례해 정하고, 주변 글씨·그림과 겹치면 적용하지 않는다. 구체적인 상한은 시제품에서 조절한다.

### 결과 예시

- `오늘은 시험 준비`에서 같은 단어 안의 불규칙한 글자 간격을 줄이되 단어 사이 공백은 유지한다.
- `AI 수업 10.5점`에서 한글·영문·숫자가 함께 있어도 소수점과 글자 순서를 보존한다.
- `-3`, `1,000`, `A1`, `0/O`, `1/l`처럼 혼동할 수 있는 요소는 원래 획을 유지하고 확신이 낮으면 보정하지 않는다.
- 밑줄, 화살표, 체크 표시, 작은 그림은 글자로 단정하지 않고 그대로 둔다.

### 보정 강도와 실패 처리

보정 강도는 ‘약하게·보통’부터 제공하는 것을 제안한다. 강도를 높여도 원래 줄과 내용 보존 원칙은 유지한다. ‘강하게’는 사용자가 원하는 변화량을 확인한 뒤 추가한다.

자동 보정 중 사용자가 같은 영역을 고치면 오래된 결과는 폐기한다. 요청이 실패하거나 연결이 끊겨도 필기는 계속되고 원본이 남아야 한다. 서버 응답이 늦어졌다고 전체 필기 화면을 잠그지 않는다. 판단하기 어려운 경우에는 ‘이 부분은 원본을 유지했어요’처럼 결과를 짧게 설명한다.

## 4 핵심 기능 둘 손글씨 연습

### 자기 글씨 다듬기

사용자가 직접 쓴 짧은 문장이나 선택한 노트 구간에서 연습을 시작한다. 첫 피드백은 간격과 정렬처럼 설명할 수 있는 항목에 집중한다.

1. 원래 글씨를 확인한다.
2. 오늘 고칠 한 가지를 정한다. 예: 같은 단어 안에서 글자 사이 간격을 비슷하게 유지하기.
3. 가이드선과 예시를 보고 짧게 연습한다.
4. 가이드를 숨기고 다시 쓴다.
5. 이전 결과와 비교하고 다음 연습을 제안한다.

보정된 내 글씨를 연습 예시로 쓸 경우 사용자가 먼저 결과를 확인하도록 한다. AI가 만든 결과를 검증 없이 정답으로 취급하지 않는다.

### 예쁜 글씨 따라 쓰기

여러 글씨체의 예시를 먼저 보여주고 사용자가 원하는 스타일을 선택한다. 특정 스타일 하나를 미리 고정하지 않는다. 선택한 뒤 ‘따라 쓰기 → 옆에 보고 쓰기 → 예시 없이 쓰기’ 순으로 연습한다. 첫 연습 언어 범위는 보정 언어와 별도로 결정한다.

스타일 선택 화면은 같은 짧은 문장을 비슷한 크기로 보여줘 모양을 비교하기 쉽게 만든다. 예시에는 지원되는 언어의 글자와 숫자를 포함하고, 스타일 이름과 확대 미리보기를 제공한다. 초기 후보 수는 2~3개를 제안하며 실제 스타일과 자료는 이후 시제품에서 확인한다. 예시를 보고 짧게 써본 뒤 연습을 시작하거나 다른 스타일로 바꿀 수 있도록 제안한다.

예시 글씨는 직접 제작하거나 서비스 사용이 허용된 자료를 사용한다. 글꼴 이미지의 윤곽만으로 실제 획순을 알 수는 없으므로, 획순 안내는 별도의 예제 획 데이터가 준비될 때 추가한다.

### 피드백과 기록

- 글자 간격, 크기 일관성, 줄 정렬 등 사용자가 이해할 수 있는 항목을 보여준다.
- 한 번에 개선점 1~2개만 제안한다. 예: ‘두 번째 단어 안의 간격을 조금 좁혀 보세요.’
- 특정 스타일의 유사도와 자기 글씨의 일관성을 구분한다. 모든 손글씨에 하나의 미적 정답을 적용하지 않는다.
- 보정 전 필기를 평가하고, 연습 중 자동 보정은 끈다. 평가 이후에 참고용 정돈 결과를 보여줄 수 있다.
- 날짜별 원본과 연습 내용을 보관한다. 초기에는 정밀한 종합 점수보다 전후 비교와 구체적인 조언을 우선한다.

짧은 연습 길이는 3~5분을 기본안으로 하되 사용자 선호에 따라 정한다. 마우스로 쓴 결과와 펜으로 쓴 결과는 입력 조건이 다르므로 성장 기록에서 구분한다.

## 5 첫 출시 범위

MVP는 사용자가 핵심 가치를 실제로 경험할 수 있는 첫 버전이다. 아래 범위는 개발 순서를 나누기 위한 기준이며, 확정된 두 핵심 기능을 유지한다.

| 구분 | 첫 출시 목표 | 이후 확장 |
| --- | --- | --- |
| 기본 노트 | 노트 생성·이름 변경·페이지 추가·펜·지우개·선택·실행 취소·다시 실행 | 폴더·다양한 펜·표지 꾸미기 |
| 페이지 조작 | 큰 페이지·확대·축소·화면 이동·전체 보기 제안 | 미니맵·고급 탐색 |
| 노트 배경 | 빈 종이·줄노트·격자 중 최소 구성 제안 | 템플릿 묶음 |
| 필기 보정 | 한글·영어·숫자, 선택 보정과 자동 보정, 원본 비교·복원 | 개인별 고급 보정·복잡한 레이아웃 |
| 자기 글씨 연습 | 간격·정렬 중심의 짧은 연습과 피드백 | 개인별 장기 커리큘럼 |
| 따라 쓰기 | 글씨체 예시 비교·사용자 선택·짧은 예제·반복 연습 | 스타일 추가·사용자 예시 업로드 |
| 저장 | 실제 사용 기기의 자동 저장과 파일 백업·복원 제안 | 필요 시 로그인·기기 간 자동 동기화 |
| 오프라인 | 미리 준비된 웹 화면에서 필기·열람·저장 | 오프라인 AI 보정 검토 |
| 출력 | 이미지 내보내기 제안 | PDF 내보내기·공유 옵션 |
| 자료 활용 | 직접 만든 노트 | PDF 불러오기와 그 위에 필기, 사진 보정 |
| 기기 지원 | 아이패드 실사용을 우선 검증 · PC 개발·마우스 테스트 지원 | 휴대폰 사용성 확대·필요 시 설치형 앱 |

수식 보정, 공동 편집, AI 요약, 문제 생성, 음성 녹음은 첫 출시 범위에서 제외하는 것을 제안한다. 글씨 보정과 연습의 품질을 확인한 뒤 확장한다.

## 6 화면 구성과 기기별 사용

### 주요 화면

| 화면 | 주요 내용 | 대표 동작 |
| --- | --- | --- |
| 내 노트 | 최근 노트·새 노트·저장 상태 | 노트 열기 |
| 필기 화면 | 큰 노트 페이지·필기 도구·보정 모드·확대 비율 | 필기·확대·축소·이동·선택 보정·원본 복원 |
| 보정 비교 | 원본과 결과·강도·미리보기 | 적용·취소 |
| 연습 홈 | 내 글씨 다듬기·따라 쓰기·최근 기록 | 연습 시작 |
| 글씨체 선택 | 같은 문장의 스타일별 예시·확대 미리보기 | 비교·스타일 선택·시험 삼아 쓰기 |
| 연습 화면 | 예시·가이드·쓰기 영역 | 쓰기·다시 쓰기 |
| 연습 결과 | 구체적인 피드백·전후 비교 | 같은 항목 다시 연습 |
| 설정 | 보정 방식·필기 입력·저장·백업 | 기본값 변경 |

전체 이동 구조는 ‘내 노트 / 연습 / 설정’을 기본안으로 한다. 노트에서 선택한 글씨를 ‘이 글씨 연습하기’로 넘길 수 있도록 두 기능을 연결한다.

### 큰 페이지와 확대 축소

노트는 크기가 정해진 큰 종이 형태의 페이지로 구성한다. 한 페이지에 필기하고 필요할 때 확대·축소하며, 다 쓰면 새 페이지를 추가한다. 페이지의 실제 크기와 가로·세로 방향은 시제품에서 확인해 정한다.

도구 모음에 확대·축소 버튼, 현재 배율, 전체 보기를 제공하는 것을 제안한다. 확대하면 세부 필기에 집중하고 축소하면 전체 내용을 확인할 수 있게 한다. 확대된 상태에서 화면을 이동할 수 있어야 하며, 쓰기와 이동이 혼동되어 원치 않는 획이 생기지 않게 한다. PC에서는 평소 드래그로 필기하고 Shift를 누른 채 드래그하면 페이지를 이동한다. 이동 중에는 획을 생성하지 않는다. 드래그를 시작한 뒤 Shift를 놓는 경우에도 해당 이동이 끝날 때까지 필기로 바뀌지 않도록 제안한다.

아이패드의 이동·확대 제스처는 실제 필기 수단을 확인한 뒤 정한다. 마우스 조작이 잘 작동하더라도 실제 필기감과 터치 오작동 여부는 아이패드에서 별도로 확인한다.

화면 확대는 보기 배율만 바꾼다. 원본 획의 실제 크기, 간격 보정 기준과 연습 평가 기준은 노트 좌표를 기준으로 유지한다. 마우스 테스트에서도 서로 다른 확대 배율로 쓰기·선택·지우기·보정을 반복해 위치가 어긋나지 않는지 확인한다.

### PC에서 모바일로 이어지는 방식

처음부터 반응형 웹으로 개발하면 동일한 서비스 주소를 PC·태블릿·휴대폰에서 사용할 수 있다. 별도 모바일 앱으로 변환해야만 휴대폰에서 열리는 구조는 아니다. 이후 작업은 작은 화면에서의 도구 배치, 확대·이동, 터치 조작, 성능을 다듬는 데 집중한다.

컴퓨터는 개발과 마우스 기반 기능 테스트에 사용한다. 실사용 기기인 아이패드에서 필기감, 손바닥 접촉, 화면 확대와 페이지 이동, 보정 결과를 확인한다. PC와 아이패드에서 번갈아 같은 노트를 쓰는 사용 방식은 현재 요구하지 않는다. 휴대폰은 후속 확장 시 긴 필기와 짧은 연습 중 어디에 무게를 둘지 추가 결정한다.

화면 폭이 바뀌어도 노트 자체의 글씨 위치는 유지한다. 노트 좌표와 화면 좌표를 분리해 저장하고, 작은 화면에서는 노트를 축소하거나 확대·이동해서 보여준다. 화면 폭에 맞춰 노트 내용을 자동 줄바꿈하지 않는다.

마우스·터치·펜은 웹의 Pointer Events로 공통 입력을 다룰 수 있다. 필압 같은 정보는 실제 기기와 브라우저에서 제공되는 범위가 다르므로 필수 입력으로 요구하지 않는다. [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

## 7 구현 구조 제안

### 웹 화면과 저장

브라우저에서 화면 표시, 필기 입력, 실행 취소, 노트 저장, 기본적인 간격 측정을 처리한다. 필기는 완성된 이미지 하나만 저장하지 않고 획별 점 좌표·순서·시간과 색·두께를 함께 저장한다. 그래야 원래 글씨 모양을 유지한 채 글자 묶음의 위치를 옮기고 다시 편집할 수 있다.

노트와 연습 기록의 로컬 저장 후보는 IndexedDB다. 브라우저 안에 구조화된 데이터와 파일을 저장할 수 있다. 로컬 저장과 기기 간 동기화는 별개의 기능으로 설계한다. [MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

인터넷 없이 다시 열 수 있도록 화면과 필요한 자원을 미리 저장하는 기능을 추가한다. Service Worker와 캐시가 구현 후보이며, 최초 접속·자원 준비에는 인터넷이 필요하다. 저장된 화면이 없거나 브라우저 데이터를 삭제한 상태까지 오프라인 사용을 보장하지는 않는다. [MDN 오프라인 웹 앱](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation)

브라우저 저장은 백업과 다르므로, 사용자 노트를 잃지 않도록 파일 내보내기·복원을 함께 제안한다. 필기 화면에서 저장 실패를 숨기지 않고 알려준다.

### AI 보정 서버

온라인 보정 요청을 받을 서버를 웹 화면과 분리한다. 서버에는 보정 대상 구간과 필요한 주변 정보만 보내는 방식을 기본안으로 한다. 외부 AI 서비스를 사용한다면 비밀 키는 서버에서 관리한다.

권장 처리 흐름은 ‘원본 획 → 줄과 글자 묶음 추정 → 이동할 간격 계산 → 작은 범위의 보정 후보 → 내용·겹침 확인 → 적용’이다. AI가 페이지 전체 이미지를 다시 그리는 방식은 작은 글자나 기호를 바꾸기 쉬우므로 초기 보정 방식으로 채택하지 않는 것을 제안한다.

가장 먼저 검증할 부분은 한글·영어·숫자가 섞인 필기를 글자와 단어 단위로 적절히 묶을 수 있는지다. 글자를 텍스트로 읽는 기술과 원래 획을 유지한 채 정돈하는 기술은 구분해야 한다. 규칙으로 간격을 맞추는 시제품은 AI 보정의 효과를 비교할 기준선으로 사용한다.

AI가 쓸만한 후보를 만들지 못한다면 원본을 유지한다. 단순한 간격 조정만 구현된 상태를 학습된 AI 보정이 완성된 것으로 설명하지 않는다. 모델·API는 실제 필기 샘플의 보존 품질, 응답 시간, 요청 비용을 비교한 뒤 선택한다.

### 자동 보정과 편집 충돌

보정 요청에는 원본 영역의 버전과 식별자를 붙인다. 결과가 돌아올 때 같은 영역이 수정되었으면 적용하지 않는다. 펜이 화면에 닿아 있는 동안 글씨를 이동시키지 않고, 완성된 구간을 처리한다. 한 번 정리한 결과를 반복 보정해 점점 위치가 달라지는 현상도 막는다.

## 8 검증 기준

아래 항목은 출시 전 확인할 기준이다. 수치가 있는 항목은 초기 실험 제안이며 실제 성과나 확정된 성능 보장이 아니다.

| 검증 항목 | 확인 방법 | 통과 방향 |
| --- | --- | --- |
| 원문 보존 | 한글·영어·숫자·기호 혼합 표본을 사람이 전후 대조 | 출시 점검 표본에서 글자·숫자·기호의 누락·추가·변형이 없어야 함 |
| 자기 글씨 유지 | 원작성자가 결과 평가 | ‘내 글씨 같다’와 ‘더 정돈됐다’를 함께 확인 |
| 위치 보존 | 줄·문단·그림과의 관계 비교 | 줄 이동과 다른 요소 침범이 없어야 함 |
| 읽기 쉬움 | 원본과 보정본의 순서를 섞어 비교 | 보정본 선호 여부와 이유를 수집 |
| 복원 | 적용·추가 필기·취소·다시 열기 시나리오 | 원본 손실 없이 지정 상태로 복원 |
| 자동 보정 | 계속 쓰기·같은 영역 수정·빠른 모드 전환 | 늦게 온 결과가 새 필기를 덮어쓰지 않음 |
| 네트워크 실패 | 요청 중 연결 끊기·시간 초과 | 필기와 로컬 저장이 계속 가능 |
| 오프라인 | 준비된 웹을 오프라인에서 열고 필기 후 재접속 | 저장한 내용 보존, 온라인 기능 상태 명확히 표시 |
| 반응 속도 | 실제 PC·아이패드에서 필기와 보정 결과 대기 시간을 따로 측정 | 필기가 보정 요청 때문에 멈추지 않음 · 보정 결과까지 체감 대기 1~3초 목표 |
| 확대와 이동 | 배율 변경, Shift와 드래그, 필기·선택·지우기·보정·저장 후 다시 열기 | 이동 중 획이 생기지 않고 입력 위치·표시 위치가 일치하며 원본 배치 유지 |
| 글씨체 선택 | 예시 비교·선택·연습 시작·다른 스타일로 변경 | 고른 예시와 실제 연습의 기준이 일치함 |
| 연습 효과 | 가이드·자동 보정 없이 처음과 나중의 글씨 비교 | 연습하지 않은 문장에서도 변화가 있는지 확인 |

초기 사용자 검증은 대학생·시험 준비생 5~10명에게 서로 다른 필기 샘플을 받는 것을 제안한다. 제품 개발에 쓰는 샘플과 최종 품질 점검 샘플을 나누고, 한글만·영문만·숫자와 기호·혼합 문장을 각각 확인한다. 작은 표본의 결과를 전체 사용자의 정확도로 일반화하지 않는다.

## 9 개발 순서

| 단계 | 만드는 것 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| 1 필기 실험 | PC와 아이패드에서 열리는 큰 노트, 확대·축소·이동, 획 저장, 지우개, 실행 취소 | 마우스·터치 입력과 배율에 따른 좌표 처리, 저장·복원이 안정적 |
| 2 선택 보정 실험 | 영역 선택, 간격 정리 기준선, AI 후보 비교, 원본 비교 | 원문·자기 글씨·줄 배치를 유지하며 정돈되는 샘플 확보 |
| 3 기본 노트 완성 | 여러 페이지, 자동 저장, 백업, 오프라인 필기 | 앱을 다시 열거나 연결이 끊겨도 작업을 이어갈 수 있음 |
| 4 두 연습 모드 | 자기 글씨 다듬기, 예시를 보고 선택하는 따라 쓰기, 기록 | 선택한 스타일이 연습에 반영되고 실제 작성한 글씨를 바탕으로 피드백 |
| 5 자동 보정 | 멈춤 감지, 영역 버전 확인, 취소·실패 처리 | 새 필기를 방해하거나 덮어쓰지 않음 |
| 6 모바일 검증 | 태블릿·휴대폰 도구 배치, 확대·이동, 실사용 테스트 | 대상 기기의 주요 흐름이 작동하고 필기감 평가 통과 |
| 7 첫 공개 | 두 핵심 기능, 사용 안내, 오류 수집 | 품질 기준 충족과 운영 비용 확인 |

아이패드 테스트는 1단계부터 진행한다. 6단계는 모바일을 처음 확인하는 시점이 아니라 사용성을 집중적으로 다듬는 단계다. AI 보정의 기술 검증을 초반에 배치해 꾸미기와 부가 기능을 많이 만든 뒤 핵심 기능의 한계를 발견하는 일을 줄인다.

고정된 마감일과 주당 개발 시간은 두지 않고, 질문과 작은 시제품을 주고받으며 진행한다. 한 번에 서로 관련된 질문 2~3개를 정리하고, 답변을 기획서에 반영한 뒤 확인할 수 있는 단위로 구체화한다. 사용해봐야 알 수 있는 선호는 미정으로 남겨 시제품에서 비교한다.

첫 실험·실사용 가능한 첫 버전·정식 공개를 별도 이정표로 관리한다. 단계별 작업은 AI 도구가 코드를 작성하더라도 실제 기기에서 직접 확인한다. 예상 기간이 필요해지면 그때의 남은 작업과 개발 여건을 기준으로 산정한다.

## 10 운영과 수익화

초기에는 본인과 소규모 테스트 사용자가 기능의 가치를 확인하는 데 집중하는 것을 제안한다. 로그인·결제·동기화의 도입 시점은 별도로 결정한다.

AI 비용은 ‘보정 1회 평균 비용 × 사용자당 보정 횟수 × 활성 사용자 수’로 가늠하고, 서버·저장소 비용을 더해 관리한다. 자동 보정은 요청 횟수가 많아질 수 있으므로 완성된 구간을 묶고 중복 요청을 줄이는 설계가 필요하다. 공급자와 측정 자료가 없으므로 현재 월 비용과 구독 가격은 정하지 않는다.

수익 모델 후보는 기본 노트 무료와 고급 보정·연습 유료, 월 구독, 일회성 구매다. 온라인 AI 운영비가 발생하므로 가격을 정하기 전에 실제 사용량을 측정한다. 필기 데이터를 모델 개선에 사용하는 것은 일반 서비스 처리와 구분해 별도 선택으로 설계하는 것을 제안한다.

## 11 유사 기능과 차별화 가설

Apple은 Notes에서 자기 글씨의 느낌을 유지하는 자동·수동 보정을 안내하고 있다. 따라서 ‘내 글씨를 정돈한다’는 설명만으로 차별성을 단정하기 어렵다. [Apple 손글씨 보정 안내](https://support.apple.com/en-my/121259)

Goodnotes의 Restyle은 선택한 손글씨를 제공되는 스타일로 바꾸고 되돌릴 수 있는 기능을 안내한다. 이 문서에서 확인한 지원 언어 목록에는 한국어가 포함되어 있지 않다. 이는 Restyle의 해당 안내 기준이며 Goodnotes 전체의 한국어 기능을 뜻하지 않는다. [Goodnotes Restyle 안내](https://support.goodnotes.com/hc/en-us/articles/16949862110735-Restyle-your-handwriting)

이번 서비스의 차별화 가설은 ‘한국어 학습 필기에서 자기 글씨와 페이지 배치를 보존하는 작은 정돈’과 ‘그 필기를 개인별 연습으로 연결하는 경험’이다. PC·태블릿·휴대폰에서 같은 웹을 사용할 수 있다는 점도 검증할 가치가 있다. 경쟁 제품보다 낫다는 주장은 같은 샘플을 비교하기 전에는 하지 않는다.

위 외부 기능 설명은 2026년 10월 23일 확인한 공식 안내 기준이다. 모델·브라우저·제품 지원 범위는 개발을 시작할 때 다시 확인한다.

## 12 추가로 결정할 질문

이미 결정된 사항은 1절에 모았다. 아래 질문은 다음 기획 버전에서 구체화할 항목이며, 정해진 항목부터 답해도 된다.

### 가장 먼저 정할 질문

1. 실제 아이패드 필기는 디지털 펜, 손가락, 둘 다 중 어떤 방식으로 할 예정인가?
2. 아이패드의 모델과 운영체제 버전은 무엇이며, 손가락 외에 사용할 디지털 펜이 있는가?
3. 큰 페이지는 세로로 긴 종이와 가로로 넓은 종이 중 어느 쪽을 기본으로 원하는가?
4. 자동 보정은 글자 몇 개, 한 단어, 한 줄 중 어느 단위가 가장 자연스러울 것 같은가?
5. 글씨체 예시를 고를 때 바로 따라 써보는 체험도 필요한가, 우선 미리보기만 있으면 되는가?
6. 노트를 처음 열면 페이지 전체를 먼저 보고 싶은가, 바로 글씨를 쓸 수 있는 배율로 시작하고 싶은가?

### 보정 경험

7. 간격 외에 다음으로 개선하고 싶은 것은 글자 크기, 기울기, 줄 정렬, 획 떨림 중 무엇인가?
8. ‘살짝만 보정’했을 때 원하는 변화가 충분한지 판단할 수 있는 본인의 필기 예시가 있는가?
9. 자동 보정 결과가 마음에 들지 않을 때 단어 단위와 방금 보정한 구간 단위 중 어떤 되돌리기가 편한가?
10. 애매한 부분은 그대로 두는 편과 결과 후보를 보여주고 선택하게 하는 편 중 무엇이 좋은가?
11. 제목, 밑줄, 화살표, 색 구분, 작은 낙서를 어느 정도 자주 사용하는가?
12. 영어는 인쇄체 위주인가, 이어 쓰는 필기체도 중요한가?

### 손글씨 연습

13. 첫 연습 콘텐츠도 한글·영어·숫자를 함께 지원해야 하는가, 한글부터 시작해도 되는가?
14. 연습 문장은 제공된 짧은 문장, 본인이 입력한 문장, 실제 노트 내용 중 무엇을 먼저 원하는가?
15. 피드백은 점수, 색으로 표시된 문제 구간, 짧은 문장 설명 중 어떤 방식이 좋은가?
16. 연습 시간을 직접 정하는 것과 하루 3~5분 분량을 추천받는 것 중 무엇이 좋은가?
17. 연습 기록은 전후 글씨 비교, 연속 연습일, 항목별 변화 중 무엇을 가장 보고 싶은가?

### 노트와 모바일

18. 처음 필요한 노트 배경은 무지, 줄노트, 격자 중 무엇인가?
19. 확대·축소 외에 현재 위치를 보여주는 작은 전체 지도도 필요한가, 전체 보기 버튼으로 충분한가?
20. 휴대폰에서도 긴 필기를 해야 하는가, 노트 확인과 짧은 연습이 주목적인가?
21. 아이패드의 노트를 백업할 때 노트 한 권씩 내보내기와 전체 노트 묶음 내보내기 중 무엇이 먼저 필요한가?
22. 다른 사람에게 결과를 보여줄 때 이미지와 PDF 중 무엇이 먼저 필요한가?

### 서비스 운영

23. 처음에는 개인용으로 검증할 것인가, 주변 학생에게도 바로 써보게 할 것인가?
24. 서버와 AI 사용료로 매달 감당할 수 있는 예산은 어느 정도인가?
25. 최종적으로 무료 서비스, 일부 유료 기능, 구독 서비스 중 어떤 방향을 생각하는가?
26. 앱 이름과 화면 분위기는 공부 도구처럼 단정한 느낌과 문구·다이어리처럼 꾸미는 느낌 중 어디에 가까운가?
