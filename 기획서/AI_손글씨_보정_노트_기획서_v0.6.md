# AI 손글씨 보정 노트 서비스 기획서

버전 0.6 · 수정일 2026년 10월 24일

대학생과 시험 준비생을 위한 서비스로, 손글씨를 보정하는 노트와 원하는 글씨체를 익히는 연습모드를 제공한다. 아이패드에서 실제로 사용하는 반응형 웹으로 개발하고, 컴퓨터는 개발과 마우스 테스트에 사용한다.

노트에서는 작성한 글씨를 자기 글씨체 보정본이나 선택한 이상적인 글씨체로 바꿀 수 있다. 연습모드에서는 제공되는 흐린 한글 예시 위에 직접 따라 쓰며 목표 글씨체를 익힌다. ‘바꾸기’는 노트에서만 제공한다. 연습모드는 직접 쓴 글씨와 목표 예시를 비교하며, 글씨를 자동으로 바꾸거나 점수를 표시하지 않는다.

이 문서의 ‘확정’은 제품 방향이 결정되었다는 뜻이며 구현 완료를 뜻하지 않는다. ‘제안’은 시제품에서 확인할 기본안이다. 현재 1단계 필기 시제품을 구현하고 PC 동작을 확인했다. 실제 아이패드 확인과 AI 품질 검증은 남아 있다. 실행 방법과 확인 결과는 [시제품 안내](../note-web/README.md)에서 확인한다.

노트의 보정 언어와 연습모드의 언어는 별개다. 노트는 한글·영어·숫자를 다루고, 연습모드는 한글 콘텐츠에 집중한다. 화면 이름과 문서에서 기능 명칭은 ‘연습모드’로 통일한다.

초기 저장은 실제 사용하는 아이패드 안의 자동 저장과 파일 백업·복원을 제안한다. 컴퓨터와 아이패드의 자동 동기화는 현재 필수 기능으로 두지 않는다. 사용자는 아이패드 모델·운영체제·펜 모델을 현재 모른다고 답했다. 이를 미확인으로 기록하고, 실제 기기 테스트를 시작할 때 입력 인식과 저장 동작을 함께 확인한다.

## 2 두 기능의 역할

| 구분 | 노트 | 연습모드 |
| --- | --- | --- |
| 사용 목적 | 공부 내용을 기록하고 읽기 좋게 정돈 | 원하는 한글 글씨체를 직접 익힘 |
| 글씨의 출처 | 사용자가 자유롭게 필기한 내용 | 서비스가 제공하는 한글 예시 |
| 작성 방법 | 빈 페이지에 자유롭게 쓰기 | 흐린 예시 위에 겹쳐 쓰기 |
| 비교 기준 | 작성 원본과 보정·변환 결과 | 직접 쓴 글씨와 목표 예시 |
| 글씨 변경 | 설정한 방식으로 보정·변환 가능 | 직접 작성한 글씨를 그대로 유지 |
| 주요 동작 | 선택 보정·자동 보정·바꾸기·되돌리기 | 목표 선택·따라 쓰기·비교·다시 쓰기·다음 |

검증할 가설은 두 가지다. 노트에서는 간격과 배치를 정리한 결과가 복습하기 편한지 확인한다. 연습모드에서는 예시 위에 따라 쓰는 과정을 반복했을 때, 예시 없이 직접 쓴 글씨도 목표 글씨체에 가까워지는지 확인한다. 화면에서 자동으로 바뀐 글씨를 사용자의 실력 향상으로 평가하지 않는다.

## 3 노트 기능

### 기본 필기

노트 생성·이름 변경·페이지 추가, 펜, 지우개, 영역 선택, 실행 취소와 다시 실행을 제공하는 것을 제안한다. 필기는 획별로 저장하고, 화면을 확대하거나 다른 페이지를 열어도 내용이 보존되어야 한다.

2026년 10월 24일 사용자 요청에 따라 흰 배경 전체를 실제 필기 영역으로 변경했다. 고정 크기 종이의 경계를 두지 않고, 화면을 이동한 곳에도 계속 쓰는 무한 캔버스 방식이다. 이전의 유한한 큰 종이 방향은 이 요구로 대체한다. 화면 폭이 바뀌어도 글씨를 자동 줄바꿈하지 않으며, 보기 배율과 위치를 바꿔 내용을 탐색한다. 페이지 구분은 이후 내용을 나누는 기능으로 제공하며 한 페이지의 필기 면적을 제한하지 않는다.

페이지를 처음 열거나 페이지 미리보기를 누르면 작업 화면을 채우는 흰 노트를 100% 배율로 보여준다. ‘10%까지만’이라는 추가 요청은 최소 축소 배율로 해석하여 조절 범위를 10~100%로 구현했다. 버튼·휠·두 손가락 확대에 같은 범위를 적용하고, ‘100%로 보기’로 기본 배율에 돌아온다. 재접속 시 마지막 화면 중심을 유지하되 저장된 배율 대신 100%로 시작한다.

### 무지와 안내선

새 노트는 무지로 시작한다. 줄노트·격자 안내선을 필요할 때 켜고 끌 수 있게 한다. 첫 조작안은 ‘없음 / 줄 / 격자’ 선택이다.

안내선은 필기와 분리해 표시한다. 안내선을 전환해도 글씨의 위치·크기·내용은 달라지지 않는다. 확대·축소와 화면 이동 시에는 종이와 같은 좌표 기준으로 움직인다. 노트마다 마지막 표시 상태를 기억하는 것을 제안한다. 안내선 간격·진하기 조절과 출력 포함 여부는 후속 결정 사항이다.

### 보정과 변환

| 설정 | 결과 | 품질 기준 |
| --- | --- | --- |
| 내 글씨체 보정 | 작성한 획의 특징을 유지하면서 간격·정렬을 자연스럽게 정돈 | 자기 글씨의 느낌과 원문 내용 유지 |
| 이상적인 글씨체 | 예시에서 선택한 목표 스타일로 작성 내용 변환 | 선택한 스타일 반영과 원문 내용 유지 |

두 방식 모두 원래 줄과 문단 구성을 최대한 보존하고, 주변 그림이나 글씨를 침범하지 않도록 한다. 맞춤법·문법·문장의 의미를 바꾸는 기능으로 사용하지 않는다.

변환 후에도 글씨의 일부 영역을 지우고 그 위치에 펜으로 덧쓸 수 있어야 한다. 글자나 단어 전체를 삭제하는 기능만으로는 이 요구를 충족하지 않는다. 시제품에서는 부분 지우기, 추가 필기, 실행 취소, 저장 후 재열기를 함께 확인한다. 출력 데이터 형식은 이 동작을 확인한 뒤 정하며, 원래 작성자의 실제 획순을 역으로 복원해야 한다는 요구는 두지 않는다.

스타일을 바꾸면 글자 폭과 모양이 달라질 수 있다. 원문 보존과 기존 줄·주변 요소 보호를 우선하고, 선택한 영역에 넣기 위해 글씨를 과도하게 찌그러뜨리거나 다른 줄로 옮기지 않는 것을 제안한다. 이 조건을 지키기 어려운 구간은 원본을 유지하고 알려준다. 목표 스타일이 지원하지 않는 문자를 다른 문자로 대체하지 않는다.

자기 글씨체 보정의 우선순위는 글자 간격과 전체 정돈이다. 글자 크기 편차·기울기·획 떨림은 보조 항목으로 검토한다. 자음·모음 구조를 적극적으로 바꾸는 처리는 별도 품질 검증 뒤 검토한다. 초기 보정 강도는 ‘약하게 / 보통’을 제안한다.

원문의 띄어쓰기는 유지한다. `10.5`, `-3`, `1,000`, `A1`처럼 작은 기호나 간격이 의미에 영향을 주는 내용을 별도로 확인한다. 수식, 그림, 화살표, 밑줄 등은 글씨로 단정해 바꾸지 않는다. 변환을 확신할 수 없으면 원본을 유지한다.

### 수동과 자동 실행

수동 실행은 영역을 선택해 결과 생성을 요청하는 방식이다. 원본과 결과를 나란히 보고 ‘바꾸기’를 누르면 적용하며, 취소하면 원본을 유지한다.

자동 실행은 작성 분량과 관계없이 잠깐 멈췄을 때 시작한다. 글자 수·단어 수·한 줄 완성을 실행 조건으로 요구하지 않는다. 마지막 입력 이후의 대기 시간을 기준으로 최근 작성 구간을 처리하며, 이어 쓰면 멈춤 감지를 다시 시작하도록 제안한다.

멈춤을 감지하는 정확한 시간은 시제품에서 조절한다. 멈춤 감지와 서버 처리를 합친 체감 대기 시간을 약 1~3초 목표로 측정한다. 한글 글자의 일부만 쓴 상태에서 멈출 수도 있으므로, 미완성 획을 다른 글자로 확정해 바꾸지 않아야 한다. 자동 실행 여부와 결과를 안전하게 적용할 수 있는지는 구분한다.

멈춤은 후보 생성의 시작 조건이다. 작성 중인 글자를 확신할 수 없으면 ‘바로 적용’에서도 해당 부분을 원본으로 둔다. 멈춤 뒤 이어 썼다면 같은 구간의 이전 요청을 폐기한다. 1~3초는 모든 분량과 네트워크에서 보장하는 값으로 표기하지 않고, 시험한 기기·요청 범위·네트워크 조건과 함께 측정한다. 지연 중에는 처리 상태를 표시하고 필기를 계속 허용한다.

| 설정 | 선택지 | 결정하는 내용 |
| --- | --- | --- |
| 변경 방식 | 내 글씨체 보정 / 이상적인 글씨체 | 어떤 모양으로 바꿀지 |
| 실행 방식 | 선택 후 실행 / 자동 실행 | 언제 결과를 만들지 |
| 자동 결과 적용 | 바로 적용 / 비교 후 적용 | 결과를 즉시 적용할지 확인할지 |

자동의 ‘비교 후 적용’은 준비된 결과가 있음을 표시하고 사용자가 비교 화면을 열도록 제안한다. 큰 비교 화면을 매번 강제로 열어 필기를 끊지 않는다. ‘바로 적용’에도 원본 보기와 되돌리기를 제공한다.

설정만 바꿨다고 기존 글씨나 대기 중인 결과를 일괄 변경하지 않는다. 처리 중 대상 영역을 다시 쓰거나 설정을 바꿨다면 오래된 결과는 폐기한다. 연결이 끊기거나 요청이 실패해도 필기와 저장은 계속되어야 한다.

## 4 연습모드

### 목적과 제공 콘텐츠

연습모드는 사용자가 원하는 이상적인 글씨체를 직접 익히는 한글 글씨체 학습 기능이다. 서비스가 제공하는 목표 예시를 선택하고 그 위에 직접 따라 쓴다. 초기 콘텐츠의 출처는 서비스가 제공하는 예시이며, 사용자 입력 문장이나 노트 내용을 가져오는 기능은 첫 범위에 포함하지 않는다.

진행 순서는 ‘자음·모음 → 글자 → 단어 → 문장’이다. 각 단계의 콘텐츠 수, 반복 횟수, 이전·다음 단계로 이동하는 규칙은 추가로 정한다. 순서 안내와 단계 잠금은 별개이며, 단계 건너뛰기를 막을지는 아직 정하지 않았다.

| 단계 | 콘텐츠 예시 | 확인할 요소 |
| --- | --- | --- |
| 자음·모음 | ㄱ, ㄴ, ㅁ, ㅏ, ㅓ 등 | 기본 획과 모양 |
| 글자 | 가, 나, 한 등 | 한 글자 안의 구성과 비율 |
| 단어 | 하루, 공부 등 | 글자 크기와 간격 |
| 문장 | 오늘도 한 줄을 써 봅니다 | 줄 정렬과 일정한 간격 |

위 내용은 콘텐츠 구성 예시이며 최종 교재는 아니다. 실제 예시 글씨는 직접 제작하거나 서비스에 사용할 수 있는 자료를 확보한다.

### 목표 글씨체 선택

같은 한글 문장을 여러 글씨체로 보여주고 사용자가 원하는 스타일을 고르게 한다. 예시 크기를 맞추고 확대해서 볼 수 있게 하는 것을 제안한다. 초기 스타일 수는 2~3개를 제안하되, 구체적인 글씨체는 예시를 확인한 뒤 결정한다.

목표 글씨체를 바꿔도 이전에 직접 쓴 기록은 그대로 남기고 당시 목표 스타일을 함께 기록하는 것을 제안한다. 목표 스타일 변경과 작성한 글씨의 자동 변환은 구분한다.

### 기본 사용 흐름

1. 연습모드에 들어가 목표 한글 글씨체를 선택한다.
2. 자음·모음 단계부터 제공되는 내용을 확인한다.
3. 화면에 흐리게 표시된 목표 예시 위에 펜이나 손가락으로 겹쳐 쓴다.
4. 직접 쓴 글씨와 목표 예시를 비교한다.
5. 필요하면 다시 쓰고, 해당 항목을 마치면 다음 내용으로 진행한다.

목표 예시는 배경으로, 직접 쓴 획은 별도로 보관한다. 예시와 작성 획이 같은 좌표에서 확대·이동되도록 한다. 예시를 잠깐 숨겨 직접 쓴 글씨만 확인하는 기능과 나란히 비교하는 결과 화면을 제안한다.

### 결과와 기록

연습모드에는 점수와 ‘바꾸기’를 제공하지 않는다. 사용자가 직접 쓴 획을 자동으로 보정하거나 목표 글씨체로 바꾸지 않는다. 비교 화면의 기준은 목표 예시와 직접 쓴 원본이다.

간격·기울기 등 차이를 짧은 설명이나 표시로 알려줄지는 시제품을 보며 정한다. 수치 점수로 순위를 매기거나 특정 글씨체를 모든 사용자에게 유일한 정답으로 취급하지 않는다.

목표 글씨체, 콘텐츠와 단계, 직접 쓴 원본, 입력 수단, 작성 시각, 완료 상태를 저장하는 것을 제안한다. 마우스 테스트 기록과 아이패드의 펜·손가락 기록은 구분한다. 이전 기록을 다시 열어 변화가 있는지 확인할 수 있도록 제안한다.

획순 안내나 애니메이션은 아직 확정하지 않았다. 제공 예시의 겉모양만으로 획순을 단정하지 않고, 해당 기능을 넣을 경우 별도 획순 자료를 준비한다.

## 5 입력과 화면 조작

아이패드의 ‘화면 고정’은 종이 위치와 배율을 잠그는 설정이다. ‘손가락 필기’는 손가락으로 획을 만들 수 있는지 정하는 별도 설정으로 제공한다. 화면 고정을 켜도 손가락 필기가 자동으로 켜지지는 않는다.

아래 입력 우선순위를 기본안으로 제안하고 실제 기기에서 확인한다. 두 설정을 분리하는 것과 화면 고정 중 이동·확대·축소를 막는 것은 확정 사항이다.

| 입력과 조작 | 화면 고정 켜짐 | 화면 고정 꺼짐 |
| --- | --- | --- |
| 디지털 펜 | 필기 | 필기 |
| 손가락 필기 켜짐의 한 손가락 드래그 | 필기 | 필기 |
| 손가락 필기 꺼짐의 한 손가락 드래그 | 획과 이동 모두 발생하지 않음 | 종이 이동 |
| 두 손가락 이동·확대·축소 | 차단 | 허용 제안 |
| 확대·축소·100%로 보기 버튼 | 위치·배율 변경 차단 | 10~100% 범위에서 사용 |

펜 사용 시 손가락 필기를 끄는 상태를 기본안으로 제안한다. 스위치를 끄는 것만으로 손바닥에 의한 화면 이동까지 해결되는 것은 아니므로, 펜으로 쓰는 동안 발생한 손가락 이동 입력을 억제하는 처리도 함께 검증한다. 펜과 손가락을 기기에서 어떻게 구분해 전달하는지는 실제 테스트로 확인한다.

컴퓨터에서는 마우스로 필기하고 Shift를 누른 채 드래그하면 종이를 이동한다. PC에도 화면 고정 버튼을 제공한다면 고정 상태를 우선해 Shift 이동을 막는 것을 제안한다. 이동 중에는 필기 획을 생성하지 않는다.

드래그 도중 고정 상태나 Shift 입력이 바뀌어도 같은 동작이 갑자기 필기로 전환되지 않도록 한다. 펜으로 쓰는 동안 손바닥이 닿아 종이가 움직이는지도 아이패드에서 확인한다. 정확한 제스처 처리와 기본 고정 상태는 시제품에서 검증한다.

주요 이동 구조는 ‘내 노트 / 연습모드 / 설정’이다. 필기 화면은 페이지와 도구를 중심으로 구성한다. 보정 비교 화면은 원본과 결과를 나란히 보여준다. 연습모드에는 글씨체 선택, 단계별 콘텐츠, 따라 쓰기 화면과 원본 비교 화면을 제공한다. 두 기능의 설정과 기록을 구분한다.

## 7 구현 구조 제안

### 입력과 저장

필기는 완성 이미지 하나로만 저장하지 않고 획별 점 좌표·순서·시간·색·두께를 함께 보관한다. 문서 좌표와 화면 좌표를 분리해 확대·축소 후에도 입력과 표시가 맞게 한다. 화면 배율이 보정 기준이나 글씨 비교 기준을 바꾸지 않도록 한다.

마우스·터치·펜 입력을 공통으로 다루는 후보는 웹의 Pointer Events다. 필압은 실제 기기와 브라우저에서 제공하는 범위를 확인하고 필수 입력으로 요구하지 않는다. [MDN Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

기기 안 구조화된 기록 저장에는 IndexedDB를 검토한다. 기기 안 저장은 자동 동기화와 별도 기능이며, 백업을 대체하지 않으므로 파일 내보내기·복원을 함께 제안한다. 저장 실패는 사용자에게 알린다. [MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

브라우저 저장은 기본적으로 저장 공간 상황 등에 따라 정리될 수 있다. 저장 유지 요청을 검토하더라도 백업과 복원은 별도로 확인한다. [MDN 저장 유지와 정리 기준](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

백업은 노트 이미지 출력과 구분한다. 편집 가능한 원본 획, 변환 결과와 추가 수정, 페이지 설정, 연습모드 기록을 복원할 수 있는 파일 구조를 제안한다. 첫 실사용 노트를 맡기기 전, 파일을 내보낸 뒤 별도 테스트 환경에서 불러와 내용과 편집 가능 여부를 확인한다. 저장 실패·공간 부족·불완전한 백업 파일에도 기존 기록을 덮어쓰지 않아야 한다.

오프라인으로 다시 열 수 있도록 화면과 필요한 자원을 미리 저장한다. Service Worker와 캐시가 구현 후보이며, 최초 접속과 자원 준비에는 인터넷이 필요하다. 브라우저 데이터를 삭제한 뒤에도 기존 노트가 남는다고 보장하지 않는다. [MDN 오프라인 웹 앱](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation)

### 노트 AI 처리

보정 대상 구간과 필요한 주변 정보를 서버에 보내 결과를 받는 구조를 제안한다. 외부 AI를 사용한다면 비밀 키는 서버에서 관리한다. 모델·API는 실제 샘플의 원문 보존, 결과 품질, 대기 시간과 요청 비용을 비교한 뒤 선택한다.

자기 글씨체 보정은 ‘원본 획 → 줄과 글자 묶음 추정 → 간격 계산 → 작은 범위의 후보 → 원문·겹침 확인 → 적용’ 순서로 검증한다. 규칙 기반 간격 조정은 비교 기준선으로 만들 수 있으나, 이를 학습된 AI 보정이 완성된 것으로 설명하지 않는다.

이상적인 글씨체 변환은 작성 내용을 구분하고 선택한 스타일로 표현하는 별도 처리로 검증한다. 사용할 스타일의 문자 지원 범위, 원본과의 내용 일치, 부분 지우기와 펜 덧쓰기를 확인한다. 출력 형식은 부분 편집과 저장 후 복원까지 확인한 뒤 정한다. 페이지 전체를 이미지로 다시 생성하는 방식은 초기 구현안으로 채택하지 않는 것을 제안한다.

보정 요청에 원본 영역 버전, 변경 방식, 목표 스타일, 적용 설정을 포함한다. 처리나 비교 중 원본 또는 설정이 바뀌면 오래된 결과는 적용하지 않는다. 같은 결과를 반복 보정해 위치가 계속 달라지지 않도록 관리한다.

연습모드는 제공 예시와 직접 작성한 획을 표시·비교하는 흐름으로 구성한다. 노트의 자동 보정 설정을 연습모드에 적용하지 않는다. 기록 구조 역시 노트의 보정 이력과 연습모드의 직접 작성 기록을 구분한다.

## 8 검증 기준

| 항목 | 확인할 조건 |
| --- | --- |
| 노트 원문 보존 | 글자·숫자·기호의 누락·추가·의미 변경 없음 |
| 자기 글씨체 보정 | 작성자가 자기 글씨라고 느끼면서 더 정돈됐다고 평가 |
| 목표 스타일 변환 | 선택한 스타일 반영과 원문 내용 보존을 함께 확인 |
| 변환 후 편집 | 글씨의 일부 지우기·펜으로 덧쓰기·실행 취소·저장 후 재열기가 모두 가능 |
| 자동 실행 | 작성량에 관계없이 멈춤 감지 · 재입력 시 감지 재시작 · 미완성 글자 처리 확인 |
| 자동 적용 | 바로 적용·비교 후 적용 설정 준수 · 새 필기 덮어쓰기 방지 |
| 대기 시간 | 멈춤 감지 또는 수동 요청부터 결과 표시까지 측정 · 약 1~3초 목표 |
| 화면 고정과 입력 | 고정 중 위치·배율 유지 · 별도 손가락 필기 설정 준수 · 손바닥에 의한 획·이동 여부 확인 |
| 안내선 | 표시 전환 후에도 작성 획과 위치 유지 |
| 확대와 이동 | 배율 변경 후 입력·선택·지우개·보정 결과의 위치 일치 |
| 저장과 복원 | 새로 열기·연결 끊김·실행 취소·파일 복원 후 원본·변경 결과·부분 편집·연습모드 기록 유지 |
| 연습모드 예시 | 한글 목표 글씨체와 단계에 맞는 흐린 예시 표시 |
| 연습모드 원본 | 작성한 획 자동 변경 없음 · 예시와 작성 획 분리 · 점수와 바꾸기 없음 |
| 연습모드 효과 | 도움 없는 별도 글씨에서 목표 스타일에 가까워지는지 확인 |

5~10명의 대학생·시험 준비생과 초기 확인을 진행하는 것을 제안한다. 개발에 쓰는 샘플과 품질 확인 샘플을 나누고, 작은 표본의 결과를 전체 정확도로 일반화하지 않는다. 노트의 혼합 언어 필기와 연습모드의 한글 콘텐츠는 별도 항목으로 확인한다.

첫 기술 실험용으로 한글·영문·숫자·기호를 포함한 짧은 필기 표본 10~20개를 준비하는 것을 제안한다. 표본별로 적용 결과, 원문 오류, 보정하지 않은 구간, 대기 시간을 따로 기록한다. 모든 구간을 건너뛰어 원문 오류만 낮추는 결과가 좋은 보정으로 평가되지 않게 한다. 원문 오류가 발견된 자동 적용 경로는 원인을 수정한 뒤 다시 확인한다.

## 9 개발 순서

단계별 작업·완료 조건·사용자 확인 항목은 [단계별 개발 진행계획](단계별_개발_진행계획.md)에 구체화했다. 아래 순서를 기준으로 하며, 기본 획 저장은 1단계부터 제공하고 3단계에서 여러 페이지·백업·오프라인까지 확장한다.

| 단계 | 작업 | 완료 확인 |
| --- | --- | --- |
| 1 필기 화면 | 큰 무지 페이지·안내선·화면 고정·확대·축소·획 저장 | PC 마우스와 아이패드 펜·손가락 입력이 안정적 |
| 2 노트 보정 검증 | 두 변경 방식·선택 영역·나란히 비교·바꾸기·부분 지우기·추가 필기·복원 | 원문과 배치를 유지하면서 바뀐 결과도 부분 편집되는 실제 샘플 확보 |
| 3 노트 저장 | 페이지 관리·자동 저장·백업·오프라인 | 다시 열기와 연결 끊김에도 필기 유지 |
| 4 연습모드 | 한글 스타일 선택·단계별 흐린 예시·겹쳐 쓰기·원본 비교 | 목표 예시와 직접 작성한 기록이 정확히 대응 |
| 5 자동 보정 | 분량과 관계없는 멈춤 감지·적용 설정·충돌 처리 | 필기를 방해하거나 오래된 결과로 덮어쓰지 않음 |
| 6 실사용 확인 | 아이패드 장시간 사용·도구 배치·성능·오류 처리 | 주요 사용 흐름과 필기감 확인 |
| 7 첫 공개 | 안내·사용자 확인·운영 비용 측정 | 품질 기준과 운영 가능성 확인 |

아이패드 확인은 1단계부터 진행한다. 6단계는 실제 기기에서 처음 확인하는 시점이 아니라 사용성을 집중적으로 다듬는 단계다. AI 보정의 가능성과 품질을 초반에 확인하고 꾸미기와 부가 기능을 확대한다.

첫 출시 범위와 첫 기술 실험의 범위를 구분한다. 첫 실험은 한 페이지, 소수의 실제 필기 표본, 목표 스타일 1개로 입력·변환·부분 편집·복원 가능성을 확인하는 것을 제안한다. 연습모드는 4단계에서 자음·모음 예시 몇 개로 겹쳐 쓰기와 원본 비교를 먼저 확인한 뒤 콘텐츠를 확장한다. 이 축소 실험은 첫 출시의 두 핵심 기능이나 언어 지원을 삭제하는 결정이 아니다. 검증되지 않은 AI 기능의 품질과 개발 기간을 확정한 것으로 취급하지 않는다.

한 번에 서로 관련된 질문 2~3개를 정하고, 답변을 문서와 작은 시제품에 반영하는 방식으로 진행한다. 직접 써봐야 알 수 있는 선택은 미정으로 남겨 비교한다. 개발 일정과 비용은 실제 작업량·사용 기술·투입 여건을 확인한 뒤 산정한다.

## 10 운영과 수익화

초기에는 본인과 소규모 사용자로 핵심 가치를 확인하는 것을 제안한다. 로그인·결제·동기화 도입 시점은 별도로 정한다.

AI 비용은 ‘평균 요청 비용 × 사용자당 요청 횟수 × 활성 사용자 수’를 측정하고 서버·저장소 비용을 더해 관리한다. 자동 보정의 중복 요청을 줄이고, 무료 기본 노트·일부 기능 유료·구독·일회 구매는 실제 비용과 수요를 확인한 뒤 검토한다. 아직 가격과 월 예산은 정하지 않았다.

필기 데이터를 모델 개선에 쓰는 것은 일반 서비스 처리와 구분해 별도 선택으로 설계하는 것을 제안한다. 연습모드에 쓰는 예시 자료는 서비스 이용 범위를 확인해 준비한다.

## 11 유사 기능과 차별화 가설

Apple은 Notes에서 자기 글씨의 느낌을 유지하는 자동·수동 보정을 안내한다. [Apple 손글씨 보정 안내](https://support.apple.com/en-my/121259)

Goodnotes Restyle은 선택한 손글씨를 제공되는 스타일로 바꾸는 기능을 안내한다. 확인한 해당 안내의 언어 목록에는 한국어가 포함되어 있지 않다. 이는 Restyle 안내 기준이며 제품 전체의 한국어 기능을 뜻하지 않는다. [Goodnotes Restyle 안내](https://support.goodnotes.com/hc/en-us/articles/16949862110735-Restyle-your-handwriting)

이 서비스는 공부 노트의 간격·배치를 보존하는 정돈과, 사용자가 고른 한글 글씨체를 직접 익히는 연습모드를 함께 제공하는 경험을 검증한다. 경쟁 우위는 같은 샘플과 사용 흐름을 비교한 뒤 판단한다. 외부 기능 설명은 2026년 10월 23일 확인한 안내 기준이며, 구현 시 지원 범위를 다시 확인한다.

## 12 다음 결정 항목

### 연습모드

1. 한 예시를 몇 번 따라 쓴 뒤 다음으로 이동할까? 사용자가 직접 ‘다음’을 누르게 할까, 정해진 횟수를 채우게 할까?
2. 자음·모음부터 순서대로 안내하되 원하는 단계로 바로 이동할 수 있게 할까, 앞 단계 완료 뒤 다음을 열까?
3. 흐린 예시에 획순 화살표나 쓰는 순서도 표시할까, 글씨 모양만 보여줄까?
4. 목표 글씨체의 첫 후보는 어떤 예시들로 비교할까? 실제 예시를 본 뒤 선택한다.
5. 예시의 진하기·크기를 사용자가 조절하게 할까?
6. 직접 쓴 글씨와 목표 예시의 비교 화면에서 차이를 색이나 짧은 설명으로 표시할까?
7. 마지막 진행 단계와 작성 기록을 이어서 보여줄까? 글씨체별 진도를 따로 관리할까?

### 노트와 기기

8. 첫 화면에서 고정을 켜서 바로 쓰게 할까, 해제해서 위치·배율을 먼저 맞추게 할까?
9. 현재 모르는 기기 정보는 실제 아이패드 테스트 때 확인하고, 펜·손가락 입력과 손바닥 접촉 결과를 기록한다.
10. 노트 작업면은 종이 방향 제한 없는 무한 캔버스로 확정했다. 100%로 시작하는 화면과 10~100% 배율의 이동 편의성을 실제 사용으로 확인한다.
11. 보정 강도와 되돌리기 단위는 실제 샘플에서 어떻게 정할까?
12. 안내선 간격·진하기 조절과 출력 포함은 필요한가?
13. 100%로 보기 버튼 외에 현재 위치를 보여주는 작은 지도가 필요한가?
14. 백업은 노트 한 권과 전체 묶음 중 어느 단위를 먼저 지원할까?

### 운영과 화면 분위기

15. 첫 시제품은 본인만 사용할까, 주변 학생에게도 공유할까?
16. 서버와 AI 사용료로 감당할 월 예산은 얼마인가?
17. 수익화는 무료·부분 유료·구독 중 어떤 방향을 생각하는가?
18. 서비스 이름과 화면 분위기는 어떻게 정할까?

## 13 다음 산출물

[단계별 개발 진행계획](단계별_개발_진행계획.md)에 따라 1단계의 한 페이지 필기 시제품을 구현했다. 별도 손가락 필기 설정을 포함한 입력·지우개·확대·이동·화면 고정과 기본 획 저장을 제공한다. PC 동작과 자동 검사를 마쳤으며, 다음 확인은 실제 아이패드 사용이다. 2단계에서 두 보정 방식과 변환 결과의 부분 편집을 검증하고, 3단계에서 백업·복원과 오프라인 사용을 완성한다.

연습모드는 4단계에서 흐린 한글 예시와 원본 비교를 연결한다. 반복·단계 이동·획순은 기존 확정 요구로 취급하지 않으며, 진행계획의 시제품 기본안으로 먼저 확인한 뒤 조정한다.
