# AI 손글씨 보정 노트 — 단계별 개발 진행계획

작성일: 2026년 10월 23일

2026년 10월 24일 변경: 흰 배경 전체를 실제 필기 영역으로 사용하도록 노트를 무한 캔버스로 변경했다. 화면을 이동한 곳에도 계속 쓸 수 있으며, 기존의 고정 크기 큰 종이 방향은 이 요청으로 대체한다.

같은 날 배율 추가 변경: 페이지를 열면 100%로 시작하며, 확대·축소 범위를 10~100%로 설정했다. ‘10%까지만’은 최소 축소 배율로 해석해 구현했다.

기준: `AI_손글씨_보정_노트_기획서_v0.6.md`의 확정 요구사항. 이 문서는 개발 순서와 각 단계의 통과 기준을 구체화한다. 현재 1단계 시제품을 구현하고 PC 확인을 마쳤으며 실제 아이패드 확인이 남아 있다. 2~7단계 구현은 아직 시작하지 않았다.

## 1 진행 원칙

- 컴퓨터에서 개발하고, 1단계부터 아이패드에서 같은 웹을 직접 사용해 확인한다. 아이패드 접속과 입력 확인을 개발 후반으로 미루지 않는다.
- 한 번에 작은 기능을 만들고, 실제로 사용한 결과를 다음 작업에 반영한다. 기획 질문만 계속 쌓지 않는다.
- 일정은 날짜보다 완료 조건으로 관리한다. 개발 환경과 실제 보정 품질을 확인한 뒤 필요한 작업량을 다시 산정한다.
- 두 가지 노트 보정은 먼저 수동 실행으로 검증한다. 자동 보정은 수동 결과가 충분히 확인된 뒤 연결한다.
- 연습모드는 한글 예시를 직접 따라 쓰는 기능이다. 점수, 자동 보정, ‘바꾸기’를 넣지 않는다.
- 초기 기술 실험의 규모를 줄여도 최종 요구사항은 유지한다. 노트는 한글·영어·숫자, 연습모드는 한글을 지원한다.

## 2 전체 순서

| 단계 | 만들 것 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 1. 한 페이지 필기 | 큰 종이 한 장, 필기·부분 지우개, 실행 취소, 확대·이동, 입력 설정, 기본 저장 | 아이패드에서 쓰고 지우고 이동한 뒤 다시 열어도 기록이 유지됨 |
| 2. 두 가지 보정 검증 | 내 글씨체 보정·이상적인 글씨체 변환, 영역 선택, 비교·바꾸기·복원 | 실제 필기에서 내용을 유지하며 보정되고, 변환 결과도 부분 편집·저장 가능 |
| 3. 실제로 쓸 수 있는 노트 | 여러 노트·페이지, 자동 저장 상태, 편집 가능한 백업·복원, 오프라인 필기 | 여러 페이지를 작성하고 다시 열기·백업 복원·오프라인 작업을 거쳐도 내용 유지 |
| 4. 연습모드 | 한글 목표 글씨체 선택, 단계별 흐린 예시, 겹쳐 쓰기, 원본 비교 | 원하는 예시를 따라 쓰고, 자신이 쓴 글씨를 그대로 비교하며 다음 예시로 이동 |
| 5. 자동 보정 | 잠깐 멈춤 감지, 바로 적용·비교 설정, 중복 요청과 새 필기 충돌 처리 | 작성량과 관계없이 동작하면서 미완성 글자나 새 필기를 훼손하지 않음 |
| 6. 실사용 검증 | 아이패드에서 공부하며 사용, 혼합 문자·긴 페이지·입력·저장·실패 상황 점검 | 정해 둔 핵심 시나리오에서 내용 손상·유실 문제가 해결되고 한계가 기록됨 |
| 7. 첫 버전 완성·제한 공유 | 기본 안내, 작은 화면 정리, 오류 안내, 사용 비용 측정, 소규모 피드백 | 실제로 계속 사용할 수 있고, 공유 범위에 맞는 품질·비용 확인을 마침 |

1단계 결과로 필기 화면을 써보고, 2단계에서 핵심 보정의 가능성을 판단한다. 3단계 결과는 기본 노트로 사용하고, 4단계에서 연습모드까지 연결한다. 5단계 이후 자동 보정을 포함한 전체 흐름을 확인한다.

## 3 단계별 실행 내용

### 1단계 — 한 페이지에서 필기부터 확인

**목표:** 아이패드에서 필기하는 감각과 조작을 먼저 확인한다.

만들 것:

- 개발 환경과 실행 방법을 정리하고, PC와 아이패드에서 열 수 있는 웹 시제품을 만든다.
- 크기 경계 없이 흰 작업면 전체에 쓰는 노트를 보여준다. 무지에서 시작하고 줄·격자 안내선을 전환하며, 이동한 위치에도 계속 쓸 수 있다.
- 펜, 부분 지우개, 실행 취소·다시 실행, 10~100% 확대·축소, 100%로 보기를 구현한다.
- PC에서는 마우스로 쓰고, 화면 고정이 꺼져 있을 때 Shift+드래그로 종이를 이동한다. 화면 고정은 PC에서도 이동·확대·축소를 막는다.
- 아이패드에서는 펜 필기, 손가락 필기 설정, 화면 고정, 손가락 이동을 구분한다.
- 원본 획을 기본 저장하고, 저장 여부를 표시한다. 테스트 필기 표본을 보관할 수 있게 한다.

시제품의 입력 규칙:

| 입력 | 화면 고정 켬 | 화면 고정 끔 |
| --- | --- | --- |
| 펜 | 필기 | 필기 |
| 손가락 1개, 손가락 필기 켬 | 필기 | 필기 |
| 손가락 1개, 손가락 필기 끔 | 무시 | 종이 이동 |
| 손가락 2개 | 이동·확대·축소 안 됨 | 종이 이동·확대·축소 |

손가락 2개 동작은 시제품 기본안이다. 펜 사용 중 손바닥 접촉으로 획이나 화면 이동이 생기는지도 별도로 확인한다. 손가락 필기를 끄는 것만으로 손바닥 문제가 해결됐다고 판단하지 않는다.

사용자가 확인할 것:

- 실제 아이패드에서 10~20분 정도 써보며 글씨가 손이나 펜을 잘 따라오는지 확인한다.
- 확대 후 같은 위치를 지우고 덧쓸 수 있는지, 화면 고정과 손가락 설정이 예상대로 작동하는지 확인한다.
- 이때 기기·운영체제·펜 정보를 확인 가능한 만큼 기록한다. 현재 모델명을 모르는 것은 기획 진행을 막지 않는다.

**완료 조건:** 입력·지우개·이동의 위치가 맞고, 고정 중 화면이 움직이지 않으며, 새로 열어도 저장한 획이 남는다. PC에서만 정상인 상태는 통과로 보지 않는다.

산출물: 한 페이지 필기 시제품, 입력 조작 확인 기록, 실제 손글씨 표본.

### 2단계 — 두 가지 보정을 작은 샘플로 검증

**목표:** 핵심 기능이 실제로 원하는 결과를 낼 수 있는지 확인한다. 화면을 보기 좋게 만드는 작업보다 이 검증을 우선한다.

만들 것:

- 영역을 선택하고 수동으로 보정을 요청한다.
- 내 글씨체를 유지하면서 간격·정돈을 개선하는 방식과, 목표 글씨체로 바꾸는 방식을 각각 실험한다.
- 원본과 결과를 나란히 보여주고 ‘바꾸기’로 적용한다. 취소·원본 복원도 가능하게 한다.
- 목표 글씨체는 실제 예시를 보고 고른 1개로 먼저 검증한다.
- 적용 결과의 일부를 지우고 펜으로 덧쓴 뒤, 실행 취소와 저장·재열기를 확인한다.
- 보정 처리 중 원본을 수정하면 해당 결과를 그대로 덮어쓰지 않게 한다.

검증 방법:

- 1단계에서 직접 작성한 짧은 표본 10~20개를 사용한다. 한글·영어·숫자·혼합 문장·기호를 처음부터 조금씩 포함한다.
- 특히 소수점·음수·띄어쓰기·받침, 줄바꿈, 글씨 옆의 그림을 확인한다.
- 표본별로 원본·결과, 바뀐 내용, 건너뛴 영역, 대기 시간, 부분 편집 가능 여부를 기록한다.
- 목표 스타일의 모양만 확인하는 임시 결과와 실제 보정 결과를 구분한다. 단순 간격 조정 규칙만 사용하는 경우에도 그 상태를 명시한다.
- 후보 기술·서비스를 실제 예시로 비교한 뒤 구현 방식을 정한다. 특정 AI가 두 보정 방식을 모두 해결한다고 미리 가정하지 않는다.

이 단계에서 함께 정할 것: 글씨체 예시, 보정 강도, 유료 AI를 시험할 경우의 비용 상한. 사용자가 기술 제공자를 미리 고를 필요는 없다.

**완료 조건:** 정해 둔 표본에서 원문과 줄 구성을 유지한 유용한 결과를 확인하고, 적용·부분 지우기·추가 필기·복원·저장·재열기까지 동작한다. 원문 오류와 적용을 건너뛴 비율을 함께 기록하며, 소수 표본 통과를 전체 글씨에 대한 정확도 보장으로 해석하지 않는다.

**결과가 부족할 때:** 오류 유형을 좁혀 수정한다. 두 방식 중 하나가 미완성이면 별도로 미완료 표시를 유지한다. 저장과 연습모드의 독립 작업은 진행할 수 있지만, 검증되지 않은 변환을 자동 적용으로 확대하지 않는다.

산출물: 수동 보정 시제품, 표본 비교표, 출력 데이터와 부분 편집 방식에 대한 결정.

### 3단계 — 저장하고 다시 쓰는 노트 완성

**목표:** 1~2단계의 시제품을 일상적으로 사용할 수 있는 기본 노트로 만든다.

만들 것:

- 노트 목록·생성·이름 변경과 페이지 추가·선택을 구현한다.
- 기본 저장을 여러 노트와 페이지의 자동 저장으로 확장하고 저장 중·완료·실패 상태를 표시한다.
- 보정 전 원본, 보정 결과, 부분 편집 내용, 페이지 안내선과 필요한 설정을 저장한다.
- 노트 한 권을 편집 가능한 파일로 백업하고 다시 불러온다. 이미지 내보내기만으로 백업 기능을 완료 처리하지 않는다.
- 앱 사용에 필요한 준비를 마친 뒤 인터넷이 끊겨도 열기·필기·저장이 가능한 흐름을 만든다.
- 인터넷이 없거나 AI 요청이 실패했을 때 원본을 유지하고 재시도를 안내한다.
- 2단계에서 검증된 수동 보정을 여러 페이지에서도 사용하도록 연결한다.

**완료 조건:** 여러 페이지를 작성한 뒤 새로 열기, 페이지 전환, 연결 끊김, 백업 후 복원을 해도 내용이 유지된다. 복원한 변환 결과에도 부분 지우개와 추가 필기가 가능하다. 브라우저 안 자동 저장만으로 백업까지 완료됐다고 판단하지 않는다.

산출물: 개인용 기본 노트 버전, 백업 파일 예시, 저장·복원 확인 기록.

### 4단계 — 한글 연습모드 만들기

**목표:** 원하는 글씨체의 흐린 한글 예시를 직접 따라 쓰고 비교한다.

만들 것:

- 실제 예시를 보고 목표 글씨체를 선택하는 화면을 만든다. 처음에는 1개로 동작을 확인한 뒤 2~3개 후보를 준비한다.
- 자음·모음 → 글자 → 단어 → 문장 순서의 콘텐츠를 제공한다.
- 흐린 예시와 사용자가 작성한 획을 분리해서 표시한다.
- 직접 쓴 글씨와 목표 예시를 비교하고, 다시 쓰기·다음 예시 이동을 제공한다.
- 최근 위치와 작성 기록을 저장하고 백업·복원 범위에 포함한다.
- 예시 자료를 서비스에 사용할 수 있는지 확인한다. 노트용 목표 글씨체와 자료를 공유할 수 있어도 각 기능의 언어 범위는 별도로 검증한다.

아직 답을 정하지 않은 세부 항목은 다음 기본안으로 시제품을 만들고, 사용해 본 뒤 조정한다.

| 항목 | 시제품 기본안 |
| --- | --- |
| 반복 횟수 | 제한 없이 다시 쓰기, 사용자가 ‘다음’을 눌러 이동 |
| 단계 이동 | 권장 순서를 보여주되 원하는 단계로 바로 이동 가능 |
| 획순 안내 | 첫 시제품은 글씨 모양만 표시, 획순 안내는 별도 판단 |
| 예시 표시 | 흐린 예시를 기본 표시하고 잠시 숨겨 내 글씨만 볼 수 있게 함 |

위 기본안은 기존 사용자 확정 답변으로 취급하지 않는다. 글씨체는 실제 예시를 보고 사용자가 선택한다.

**완료 조건:** 단계별 예시를 선택하고 따라 쓴 뒤 비교·다시 쓰기·다음 이동·재접속을 할 수 있다. 예시를 숨겨도 직접 쓴 획이 남고, 노트의 보정 설정이 연습모드에 적용되지 않는다. 점수와 ‘바꾸기’는 없다.

산출물: 한글 연습모드 시제품, 초기 예시 콘텐츠, 직접 사용한 비교 결과.

### 5단계 — 자동 보정 연결

**목표:** 수동으로 확인한 보정 기능을 필기 흐름에 자연스럽게 연결한다.

만들 것:

- 글자나 줄의 분량 조건 없이 필기가 잠깐 멈추면 자동 보정을 시작한다.
- 다시 쓰기 시작하면 멈춤 판단을 새로 하고, 같은 영역에 대한 중복 요청을 줄인다.
- 자동 모드에서도 ‘바로 적용 / 비교 후 적용’을 설정할 수 있게 한다.
- 페이지 이동, 글씨 추가·지우기, 스타일 변경 뒤에는 오래된 결과가 새 상태를 덮어쓰지 않게 한다.
- 미완성 글자나 확신하기 어려운 영역은 원본을 유지한다. 멈췄다는 이유만으로 내용 완성을 추측하지 않는다.
- 실패 시 원본 유지, 재시도, 자동 보정 끄기를 제공한다.

잠깐 멈춤의 구체적인 길이는 아이패드 필기 표본으로 정한다. 사용자에게 보이는 대기 시간은 자동 모드에서는 멈춤 감지 시간을 포함해 측정한다. 1~3초는 검증할 목표이며 모든 분량에 대한 보장으로 안내하지 않는다.

**완료 조건:** 짧게 쓰기·길게 쓰기·받침을 쓰기 전 멈추기·결과 도착 전 다시 쓰기·요청 실패 상황에서 확인한다. 원문 손상과 새 필기 덮어쓰기가 없고 적용 설정을 준수해야 한다. 원문 오류가 발견된 경로는 자동 적용 범위를 늘리기 전에 수정한다.

산출물: 자동·수동 선택이 가능한 통합 버전, 대기 시간과 요청 횟수 기록.

### 6단계 — 아이패드 실사용과 품질 확인

**목표:** 개별 기능이 아니라 공부하는 전체 흐름에서 확인한다.

확인할 것:

- 아이패드에서 30~60분 정도 실제 공부 내용을 쓰고 페이지를 늘려 본다.
- 펜·손가락·손바닥 접촉, 화면 고정, 확대 상태의 선택·지우개·보정을 확인한다.
- 두 보정 방식에서 한글·영어·숫자·혼합 필기와 여러 줄을 확인한다. 최종 노트 지원 범위를 한글로만 축소하지 않는다.
- 소수점·마이너스·기호, 그림 옆 글씨, 좁은 줄 간격, 미완성 한글, 긴 페이지를 확인한다.
- 보정 결과를 다시 고친 후 저장·백업·복원하고, 연결 끊김과 AI 실패 상황을 확인한다.
- 연습모드는 예시 따라 쓰기와 비교 흐름을 확인한다. 예시 없이 쓰는 별도 표본은 개선 여부를 관찰하는 용도로 사용하며 앱에 점수를 넣지 않는다.
- 개발하면서 반복 사용한 표본과 별도로 새로운 확인용 표본을 사용한다.

문제 수정 순서: 내용 유실·내용 변경 → 입력 충돌 → 부분 편집·복원 → 대기 시간과 화면 조작 → 외형.

**완료 조건:** 확인 시나리오에서 발견된 내용 손상·유실 문제가 해결되고, 유용하게 보정되는 범위·건너뛰는 범위·알려진 한계를 설명할 수 있다. 더 이상 사용하지 못할 정도의 필기·저장 문제가 남아 있으면 다음 공유 단계로 넘기지 않는다.

산출물: 수정한 개인용 첫 버전, 확인 결과와 남은 한계 목록.

### 7단계 — 첫 버전 완성 및 제한 공유

**목표:** 본인이 계속 사용할 수 있게 정리하고, 필요한 범위부터 다른 사용자에게 확인받는다.

만들 것:

- 처음 사용할 때 필요한 필기·화면 고정·손가락 설정·보정·백업 안내를 정리한다.
- 아이패드 가로·세로 화면과 좁은 화면에서 도구가 가려지지 않게 정리한다.
- 오류·처리 중·인터넷 연결·저장 상태를 이해하기 쉽게 표시한다.
- 실제 AI 요청 수, 처리 시간, 사용 비용을 측정하고 허용 예산과 비교한다.
- 필기 데이터 처리 범위와 예시 자료 사용 조건을 확인한다.
- 본인 사용이 안정되면 대학생·시험 준비생 5~10명 정도에게 제한적으로 사용 의견을 받는 것을 목표로 한다.

**완료 조건:** 핵심 두 기능의 사용 흐름, 복원 방법, 실제 비용, 알려진 한계를 정리한다. 외부 공유·전체 공개의 범위와 시점은 결과를 보고 정한다.

산출물: 첫 버전, 짧은 사용 안내, 피드백과 다음 개선 목록.

## 4 첫 버전 이후로 미룰 항목

- PDF 강의자료·문제집 위 필기.
- 로그인, 기기 간 자동 동기화, 결제와 구독.
- 네이티브 앱 배포와 휴대폰에 특화된 추가 조작.
- 많은 목표 글씨체, 필기 검색·요약, 수식 보정 등 확장 기능.

큰 페이지, 두 가지 노트 변경 방식, 한글·영어·숫자 보정, 부분 편집, 연습모드, 자동·수동 선택은 첫 버전의 목표로 유지한다. 품질이 확보되지 않은 기능은 완료로 표시하지 않는다.

## 5 단계마다 함께 진행할 방식

1. 이번 단계의 작은 작업과 확인할 결과를 먼저 정리한다.
2. 판단에 필요한 질문만 2~3개씩 다룬다. 이미 결정한 요구사항은 반복해서 묻지 않는다.
3. 실행 가능한 시제품과 확인 방법을 제공한다.
4. 사용자는 아이패드에서 써 보고 불편한 동작과 원하는 예시를 알려준다.
5. 결과를 문서에 반영하고, 완료 조건을 확인한 뒤 다음 작업으로 넘어간다.

기술 선택과 코드 작성·오류 분석·확인 기록 정리는 개발 작업에서 처리한다. 실제 필기감, 좋아하는 글씨체, 보정 결과의 자연스러움은 사용자 확인을 반영한다. 입력 확인이나 예시 선택에 꼭 필요한 답을 기다리는 동안에도 독립적으로 할 수 있는 작업은 진행한다.

## 6 바로 다음 작업

다음 작업은 **구현한 1단계 시제품의 실제 아이패드 확인**이다. 확인 순서는 ‘큰 종이에 쓰기 → 일부 지우기 → 확대·이동 → 화면 고정과 손가락 설정 바꾸기 → 저장 후 다시 열기’다. 실제 기기 결과에 따라 입력과 화면을 수정한다.

첫 화면에는 종이와 핵심 도구를 배치했다. 도구 위치·페이지 방향·배율은 시제품 기본값으로 시작하고 사용 후 조정한다. AI 보정은 다음 기술 검증 단계에서 구현한다.

진행 상태: 1단계 시제품 구현과 PC 확인 완료. [실행 안내](../note-web/README.md)와 [검증 기록](../note-web/검증기록.md)에 실행 방법과 결과를 기록했다. 흰 작업면 전체 필기와 배율 변경 후 자동 검사 25개가 통과했다. 기존 영역 밖 필기·저장, 페이지 재선택·새로고침 시 100% 시작, 10% 축소 한도를 확인했다. 실제 아이패드의 펜·손가락·손바닥 접촉과 저장 재접속을 확인한 뒤 1단계를 완료 처리한다. 2~7단계 구현은 아직 시작하지 않았다.
